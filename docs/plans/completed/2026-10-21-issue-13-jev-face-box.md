## Goal

Jev モードでも、映像に写る顔の位置を赤枠で確認できるようにする。
顔がない画像に対して、Box の座標だけで枠を表示する問題を防ぐ。

## Scope

- 既存の姿勢判定と同じリクエストに顔用の質問を追加する。
- Noul で顔の存在を確認し、Box で顔の正規化座標を取得する。
- 応答を検証し、既存の顔枠 API の座標系へ変換する。
- 既存の CSS の赤枠を Jev モードでも使用する。
- 顔枠の取得失敗を画面へエラーとして表示する。
- 関連テストと現行仕様の該当箇所を更新する。

## Non-goals

- 新しい依存関係、設定項目、NVS 項目の追加。
- 姿勢判定の質問、うつ伏せ閾値、監視判定の変更。
- 送信周期、通信期限、再送方針、TLS 設定の変更。
- 複数の顔枠、人物追跡、フレーム同期の追加。
- JPEG への枠の焼き込み。
- Issue #10 の未完了な実機検証の完了扱い。

## Required Behavior

### 確定した要求と確認済みの現状

- MUST: Jev 1.14 の `box` 質問形式を使用する。
- MUST: 同じ画像に対する顔存在の `noul` 質問を同時に送る。
- MUST: 顔が存在しない判定では、Box の返答を表示に使わない。
- MUST: `left`、`right`、`top`、`bottom` から座標を変換する。
- MUST: 顔枠は CSS で表示する。
- 公式応答の座標は `answers.<質問 ID>.box` に入る。
- 各座標は画像の左上を原点とする 0〜1 の値である。
- Noul の返答は `answers.<質問 ID>.noul` の確率である。
- 現在の送信モデルは `jev-1.14.0` である。
- 現在の CSS 枠と表示領域は 320×240 である。
- `/health` と `/face_box` は同じ顔枠取得処理を使う。
- 現在の Jev 結果には顔の情報がない。
- 現行仕様には「Jev モードでは顔検知の枠を表示しない」とある。

### 承認済みの動作

- MUST: 顔存在の閾値を固定値 `0.5` とする。
- MUST: Noul が `0.5` 以上の場合に顔ありとする。
- MUST: 顔存在の閾値を、設定可能なうつ伏せ閾値と分離する。
- MUST: 両質問の対象を、姿勢判定対象の乳児の顔に統一する。
- MUST: 対象の乳児を一意に特定できない画像では顔なしとする。
- MUST: 顔質問の不正は、正常な姿勢判定を失敗へ変更しない。
- MUST: 顔質問が欠落または不正な場合は、枠を表示しない。
- MUST: 顔質問が欠落または不正な場合は、画面へエラーを表示する。
- MUST: 顔枠のエラーは、姿勢判定の結果と区別して表示する。
- MUST: 通信失敗とカメラ障害は、画面へエラーを表示する。
- MUST: 正常な顔なし判定を、取得失敗として表示しない。
- MUST: 後続の正常な顔回答を受けた場合は、顔枠のエラーを解除する。
- MUST: 姿勢の `unjudgeable` でも、顔回答が有効なら枠を表示する。
- MUST: 応答 JSON 全体が不正な場合は、既存のエラー扱いを維持する。
- MUST: 通信失敗、設定変更、カメラ障害時は古い枠を消す。
- MUST: 新しいリクエストの応答待ちでは、直前の有効な枠を維持する。
- MUST: 顔なしの次回結果を受けた場合は、直前の枠を消す。
- MUST: 独立した有効期限や映像の追跡処理は追加しない。

### 承認済みの座標と検証

- MUST: 顔存在確率は有限数かつ 0〜1 であることを検証する。
- MUST: Box の各座標は有限数かつ 0〜1 であることを検証する。
- MUST: `left < right` と `top < bottom` を要求する。
- MUST: 顔なしの場合は Box の有効性にかかわらず表示しない。
- MUST: 顔ありの場合は、型と座標が有効な Box だけを表示する。
- MUST: 正規化 X 座標を 320 倍し、Y 座標を 240 倍する。
- MUST: 整数への変換は非負値の小数部を切り捨てる。
- MUST: X は 0〜319、Y は 0〜239 の既存範囲へ制限する。
- MUST: 変換後に幅または高さが 0 以下の枠は表示しない。
- MUST: Box の `confidence` は有限数かつ 0〜1 を要求する。
- MUST: 顔枠 API の `confidence` には Box の値を使用する。
- MUST: Box の信頼度に対する追加の表示閾値は設けない。
- MUST: 顔なし応答の座標と信頼度は既存の無効値を維持する。
- MUST: 顔枠の結果をローカルの姿勢推定へ入力しない。

## 通信エラーの修正提案 (2026-10-21)

- Approval: approved (2026-10-21)。ユーザの「OK」により承認された。
- ユーザの実機ログで、100ms 設定の送信待機中の失敗を確認した。
- ログ: `stage=send_request status=network_error err=ESP_ERR_HTTP_WRITE_DATA`。
- 直前の transport ログは `timeout_ms=100` を示している。
- ログ単独では待機期限への到達とソケットエラーを区別できない。
- `http_status=0 received=0` のため、顔回答の解析より前に失敗している。
- `errno=No more processes` だけではプロセス数不足と断定しない。
- TLS のゼロフラグだけでは証明書検証成功と断定しない。

### 最小修正

- `main/jev_client.c` の接続後の待機時間変更を削除する。
- 対象は `esp_http_client_set_timeout_ms(event->client, 100)` の 1 行である。
- HTTP client の初期設定 `JEV_TIMEOUT_MS` (8 秒) を維持する。
- 独立タイマーによる全体 8 秒のソケット打ち切りを維持する。
- 10 秒周期、再送なし、証明書検証、顔枠処理は維持する。
- SDK、設定、依存関係は変更しない。
