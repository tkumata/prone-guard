# Issue #25 顔検知が距離で不安定になる原因の調査計画

## Status

- Phase: investigation_completed (2026-11-05)
- Approval: approved (2026-11-05、調査範囲)
- Branch: `fix/issue-25`

## Goal

カメラから約 30 cm では顔検知が安定する。
約 30 cm を超えると顔検知が急に不安定になると報告された。
まず、約 30 cm の前後で検知が急に変わる原因を切り分ける。
調査結果をもとに、目標距離の 3 m で安定して検知するための対策を提案する。

## Scope

- ESP32-S3 のカメラ入力から顔検知の成立判定までを調査する。
- 現行コードと Espressif の実装を照合し、モデルの使い方を確認する。
- 実機で取得できる測定値と再現条件を整理し、対策候補を比較する。

## Non-goals

- 顔の照合や個人の特定。
- 対策の実装、モデルの切替、依存関係の更新。
- エッジ側の判定、観測 API、TFT 表示の変更。

## Required Behavior

- MUST: 検知対象は乳幼児を含む人の顔とする。
- MUST: 現行の JPEG 取得、回転・余白、モデル入力、候補抽出、閾値を確認する。
- MUST: Issue の報告、コードで確認できた事実、原因の仮説、実測結果を区別する。
- MUST: 3 m での安定検知は改善の目標とし、実測値と合意した基準で達成を判断する。

## Tasks

### Task 1: 現行の顔検知経路とモデルの使い方を確認する

- Objective: 約 30 cm を超えた直後に検知が不安定になる箇所の候補を特定する。
- Scope: `main/main.c`、`main/prone_inference_bridge.cpp`、`main/face_rotation.h`、固定版の依存コンポーネント。
- Acceptance Criteria: 元画像からモデル入力までの寸法変化を示す。MSR と MNP の役割を説明し、公式の使い方と現行実装の差分を示す。各仮説を切り分ける観測項目を挙げる。
- Verification: `dependencies.lock` のバージョンを基準に、公開資料、依存コンポーネントの実装、現行コードを照合する。

### Task 2: 距離別の再現方法と対策候補をまとめる

- Objective: Task 1 の仮説を検証する手順を示し、次に試す対策を提案する。
- Scope: 約 30 cm の直前・直後での再現を優先する。入力画像、前処理、検知閾値、対応するモデルを候補として扱う。3 m は改善後の評価距離とする。
- Acceptance Criteria: 同一の照明・姿勢で距離を変え、検知率と未検知の連続時間を記録できる手順を示す。顔が映らない条件で誤検知も確認する。各対策を期待効果、誤検知、処理時間・メモリ、1 秒周期への影響で比較する。
- Verification: 既存の顔検知ログで確認できる項目と追加計測が必要な項目を分ける。実機と協力者を確保できる範囲で現行動作を測定し、取得できない結果は未検証として記録する。

## 調査結果

### Task 1 現行経路とモデルの使い方

依存関係は ESP-DL 3.3.14、human_face_detect 0.5.1、esp32-camera 2.1.8。
モデルファイルの入出力テンソルと、固定版の前処理・後処理を照合した。

| 段階 | 確認した処理 |
| --- | --- |
| 撮影と前処理 | VGA の JPEG を 640×480 の RGB888 にデコードする。異なる寸法の入力は VGA に変換する。反時計回りに 90 度回し、480×640 の画像を黒い余白付きの 856×642 に配置する。 |
| MSR | キャンバス全体を 160×120 に縮小する。顔が映る領域は約 90×120 になり、顔の各辺は元画像の約 18.7% になる。スコア閾値 0.30 と NMS の IoU 閾値 0.45 を使い、候補を最大 10 件残す。 |
| MNP | MSR の候補矩形を縮小前のキャンバス上で正方形に切り出し、48×48 に変換する。候補ごとに矩形とランドマークを推定する。MSR で候補が残らなければ MNP は実行されない。 |
| 観測 | 最もスコアの高い結果を選ぶ。余白と回転を戻し、320×240 座標に縮小・クリップする。変換後の矩形が有効なとき、顔検知成立として観測へ記録する。 |

公式の `HumanFaceDetect` も、同じモデルを指定すると内部で同じ `MSRMNP` を生成する。
現行コードはラッパーを経由せず `MSRMNP` を直接生成する。
RGB888 の画像を `run()` に渡す使い方はコンポーネントの API と整合する。
MSR と MNP の既定スコア閾値・NMS 閾値はすべて 0.50 である。
現行コードは入力の回転・余白と閾値を独自に設定する。

MNP のスコア出力は 2 要素で、固定版の後処理は softmax の最大値を返す。
そのため、有限の出力に対するスコアの下限は 0.50 になる。
MNP の 0.35 とアプリの最終閾値 0.35 は、スコアで候補を除外できない。
この値だけでは顔クラスの確率を判断できない。

MSR の縮小は全距離で行われる。コード上、約 30 cm で前処理や閾値を切り替える処理は確認できなかった。
顔の画像上の寸法が少しずつ変わり、MSR のスコアが閾値を下回ると、検知結果は急に変わりうる。
報告された変化がどの段階で起こるかは、約 30 cm の前後で次の項目を照合して判断する。

| 約 30 cm の前後で確認する変化 | 切り分ける箇所 |
| --- | --- |
| 元の JPEG で顔の鮮明さが変わる | ピント、露出などの撮影条件。顔の画素寸法と鮮明さを分けて記録する。 |
| JPEG は鮮明で、顔に重なる MSR 候補だけが減る | 縮小後の顔の寸法、MSR のスコア閾値、NMS による候補の除外。 |
| MSR の正しい候補は残り、観測で未検知またはエラーが増える | MNP が返す矩形、最高スコアの候補の選択、320×240 への座標変換。 |
| 取得エラーや古いフレームが増える | カメラの取得経路。モデルの未検知と別に集計する。 |

### Task 2 エミュレーターでの再現試験

公開写真の右側を使い、頭から腹まで写る範囲を切り出した。
顔の中心を固定し、人物の大きさを変えた 640×480 の JPEG を生成した。
顔幅は切り出し画像から見積もった概算値である。
実機の撮影距離への換算は行っていない。

Espressif の ESP32-S3 エミュレーター 0.51.0 上で、固定版のモデルを実行した。
現行経路では、既存の JPEG デコード、回転・余白、判定処理を通した。
調査用のコピーにログを加え、MSR と MNP の候補数を記録した。
比較用の ESPDet-Pico 416 には、回転後の縦長画像を渡した。
ESPDet-Pico 416 は既定のスコア閾値 0.50 で評価した。

| VGA 上の概算顔幅 | 現行 MSR の候補数 | 現行の最終判定 | ESPDet-Pico 416 |
| --- | --- | --- | --- |
| 100、80、64、56、48 px | 各 1 | 検知 | 検知 |
| 40、32、24、16 px | 各 0 | 未検知 | 検知 |
| 8 px | 0 | 未検知 | 未検知 |
| 顔なしの単色画像 | 0 | 未検知 | 未検知 |

現行経路では約 48 px で MSR スコア 0.4225 の候補が残った。
約 40 px では MSR の候補がなくなり、MNP に渡る前に検知が途切れた。
ESPDet-Pico 416 は約 16 px でスコア 0.5927 の矩形を返した。
検知成立時は、返った矩形に生成時の顔の中心が含まれることを確認した。

この写真では、人物を小さくするだけで現行経路の検知が途切れた。
同じ画像では、縦長入力を使う ESPDet-Pico 416 が小さい顔を検知できた。
比較ではモデルと入力の余白を同時に変えた。各変更の効果は個別に測定していない。
1 人、1 構図での結果であり、実機で約 30 cm を超えたときの原因は未確定である。

### 実機で距離別に測る場合の手順

1. カメラの画角と向き、照明、顔の向き、画面内の顔の位置を揃える。距離はレンズから顔までを測る。
2. 初回は 25・30・35・40 cm を候補とし、各距離で 60 秒測る。検知が不安定になった区間は距離の刻みを細かくして再測定する。近づく方向でも測り、距離以外の変化を確認する。顔のない同じ画角でも測る。
3. 既存ファームウェアの USB ログ `face err=...` と、利用できる場合はエッジの観測 JSONL を記録する。USB ログの時刻、`err`、`age_ms`、`score`、`box` と、JSONL の `sequence`、`camera.status`、`camera.face_detected` を使う。
4. 正常な観測に占める検知率と、検知成立のない最長時間を記録する。連続時間は実際の時刻から求め、観測エラーと欠測の区間を別記する。顔なし区間では正常な観測に占める誤検知率を記録する。
5. 原因の切り分けには、同じ入力フレームの顔矩形と鮮明さ、MSR の候補矩形・スコア、MNP の結果と変換前後の矩形を記録する。候補の閾値や NMS による脱落を区別するには、MSR の後処理前の出力も確認する。
6. 対策の比較では同じ入力フレームを使う。実機で撮影から観測確定までの時間、観測間隔、内部 RAM と PSRAM の空きと最大連続領域も比較する。
7. 対策を選んだ後、3 m で同じ指標を測り、合意した基準で改善目標の達成を評価する。

既存ログの `detected` は座標変換後の矩形の有効性を含まない。
最終判定は JSONL を優先し、USB ログだけの場合は矩形の幅と高さも確認する。
既存ログで分かるスコアは最終結果のみであり、各段階の候補と処理時間には追加計測が要る。

### 対策候補

| 対策 | 期待効果と誤検知 | 処理時間・メモリと 1 秒周期 |
| --- | --- | --- |
| 回転後の縦長画像で ESPDet-Pico 416 を比較する | 480×640 の画像を公式の letterbox 前処理に渡すと、有効画像は約 312×416 になる。モデル入力上の顔の幅と高さは現行 MSR の約 3.5 倍になる。顔なし区間で誤検知を測る。 | 公式の ESP32-S3 参考値は前処理から後処理まで約 436 ms。撮影や JPEG デコードを含む時間と、モデルを載せた状態のメモリを実機で測る。 |
| ESPDet-Pico 224 を同じ条件で比較する | 有効画像は約 168×224 になる。モデル入力上の顔の幅と高さは現行 MSR の約 1.9 倍になる。416 と検知率・誤検知率を比較する。 | 公式の参考値は約 131 ms。416 より観測周期に余裕を取りやすい。メモリと周期は実機で測る。 |
| ベッドが固定なら、MSR の入力をベッド周辺に絞る | 既存モデルのまま、撮影済みの画素を顔が現れる範囲に配分できる。範囲外の顔を見落とすため、ベッド内の端や姿勢の変化を含めて確認する。 | MSR の入力テンソル寸法は同じ。切り出しと座標復元の負荷、MNP の候補数を測る。 |
| MSR 閾値を比較する | 正しい候補が現行閾値の直下にあると確認できた場合に有効。閾値を下げると誤検知が増えうる。 | MNP に渡る候補が増えると処理時間も増える。候補数と観測間隔を測る。 |
| 撮影の画角・ピント・解像度を見直す | VGA JPEG の時点で顔が小さい、または不鮮明な場合に優先する。画角を狭める場合はベッド全体を覆えるか確認する。高解像度化は、縮小前の画素をモデル入力で活かせる構成と比較する。 | 画角・ピントの調整による推論負荷は同じ。高解像度化は取得・デコード時間と画像バッファを増やすため、周期とメモリを測る。 |

まず約 30 cm の前後で、元の VGA JPEG と MSR 候補を比較する。
元画像の鮮明さが変わる場合は、撮影条件を先に調べる。
JPEG が鮮明で MSR のスコアが現行閾値の直下にある場合は、まず閾値の影響を同じ画像で確かめる。
顔が小さく、閾値の調整では誤検知を抑えられない場合は、現行と ESPDet-Pico 416 を同じ入力で比較する。
416 の周期やメモリに余裕がなければ 224 も比較する。
両モデルは固定版コンポーネントに同梱されている。確認したビルド設定でフラッシュに組み込むのは MSR と MNP のみである。
公式の参考値では MSR は約 35 ms、MNP は候補 1 件あたり約 6 ms である。
公式のベンチマーク値は、本機の 3 m での性能を示すものではない。

### 検証状況

- 固定版モデルの入出力テンソル、前処理、後処理を確認した。
- `sh tests/run.sh` は成功した。顔矩形の座標復元を含むホストテストを確認した。
- ESP32-S3 エミュレーターで現行経路と ESPDet-Pico 416 を各 11 入力で比較した。
- 検証用ファームウェア内の ESPDet-Pico 416 のモデルは、Espressif の公式配布物と公式リポジトリのモデルにバイト単位で一致した。
- カメラのピント・露出を含む、距離別の実機測定は未実施。
