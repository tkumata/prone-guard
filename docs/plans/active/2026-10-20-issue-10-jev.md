# Issue #10: Jev を利用する

## Status

- Phase: validation_pending
- Approval: approved (2026-10-20)
- 対象 Issue: https://github.com/tkumata/prone-guard/issues/10
- 作業ブランチ: `feat/issue-10`
- ユーザの「実装をお願いします」により、記載範囲の実装が承認された。
- `espressif/cjson` の追加は別途承認済みである。
- 実装と自動検証は完了した。実 API と実機の検証は未完了である。

## Goal

カメラ画像から Jev がうつ伏せを識別できるか検証する。
映像配信を維持し、Web 画面で判定方式を切り替える。

## Scope

- Jev の画像入力と yes/no 判定の実現性を確認する。
- Jev モードでは画像を 10 秒に一回送信する。
- Web 管理画面に判定方式と API key の設定を追加する。
- API key の保存先を不揮発メモリに追加する。
- 既存の prone-like 推定と Jev 判定を切り替える。
- ビルド、境界条件、実機での映像配信を確認する。

## Non-goals

- 既存の prone-like 推定アルゴリズムの改良。
- 通知機能、別サーバ、モデル学習の追加。
- Issue と無関係な既存文書の全面改訂。
- 医療用途の認証、精度保証、人的監視の代替。

## Required Behavior

### 確定した要求

- MUST: カメラの映像配信を維持する。
- MUST: Jev への画像送信間隔を 10 秒とする。
- MUST: Web 管理画面で判定方式を切り替える。
- MUST: Web 管理画面から Jev API key を入力する。
- MUST: API key を不揮発メモリに保存する。
- MUST: Jev の判定結果を bool としてアプリ側で扱う。
- MUST: うつ伏せは `true`、それ以外は `false` に対応させる。
- MUST: 撮影サイズを VGA (640×480) とする。
- MUST: bool 変換の閾値の初期値を `0.5` とする。
- MUST: Web 管理画面から閾値を変更できるようにする。
- MUST: 判別不能な画像にはエラーを返す。
- MUST: 10 秒ごとの送信時刻に前回の応答待ちなら送信を省略する。
- MUST: 省略後は次の 10 秒後の送信時刻に再判定する。
- MUST: 送信の同時実行と遅延分のまとめ送りを行わない。
- MUST: Jev の通信は送信開始から 8 秒でタイムアウトする。
- MUST: タイムアウト後は再送せず、次の 10 秒周期の送信を待つ。
- MUST: API key が空欄の場合は、保存済みの key を変更しない。
- MUST: 保存済みの key がない場合も、空欄保存では変更しない。
- MUST: 判定方式、閾値、API key を再起動後も維持する。
- MUST: ブラウザ未接続でも撮影と Jev への送信を継続する。
- MUST: Jev との通信は HTTPS を使用する。
- MUST: Jev のモデルバージョンは 1.14 を使用する。

### 実装前の調査結果

- Jev の画像入力は試作用として公開されている。
- 公式仕様は画像の各辺を 280〜1568px と指定している。
- 現在の 320×240 画像は最小寸法を満たさない。
- 画像入力には `TypeSafe-Danger-Zone-Images: true` が必要。
- Noul は bool ではなく yes の確率を返す。
- 応答の取得先は `answers.<question>.noul` である。
- bool に変換する閾値はアプリ側で決める必要がある。
- API は `POST https://api.typesafe.ai/v1/systemone` を使う。
- 認証には `Authorization: Bearer <API key>` を使う。
- 画像の送信は multipart が公式推奨である。
- 画像対応モデルは Jev 1.13 と Jev 1.14 である。
- 画像入力の対応だけでは、うつ伏せ識別の精度は確認できない。
- 既存要件はクラウド推論を対象外としている。
- 本 Issue はクラウド推論の追加を提案する。
- 現行実装は `/stream` の接続中だけフレームを取得する。
- アプリ設定の NVS 保存と設定更新 API は未実装である。
- 既存の自動テストはなく、ビルドと実機検証が定義されている。

### 判定方法と検証方針

- Choice は選択結果と各選択肢の確率を返す。
- 実装は「うつ伏せ / それ以外 / 判別不能」の 3 択とする。
- 質問では、顔の向きではなく胴体と支持面の関係を指定する。
- 判別不能が選ばれた場合は、bool に変換せずエラーとする。
- 判別可能な場合は、うつ伏せ確率を設定閾値と比較する。
- 閾値以上は `true`、閾値未満は `false` とする。
- 本方式を実装した。実画像での識別精度は未検証である。
- 低いうつ伏せ確率だけを判別不能の根拠にしない。
- Noul 単独では判別不能と非うつ伏せを区別できない。

### 実装の対象と責務

| 対象 | 変更の責務 |
| --- | --- |
| `main/main.c` | 撮影の独立化、VGA 設定、モード切替、周期、状態表示 |
| `main/main.c` の埋め込み HTML | 設定と閾値の入力、Jev 用の判定表示 |
| 新規 Jev 通信モジュール | HTTPS、画像送信、応答検証 |
| 新規設定保存モジュール | 設定の NVS 読み書きと保存エラー |
| `main/CMakeLists.txt` | 追加ソースと標準コンポーネントの登録 |
| 小規模テスト | 周期、結果変換、切替時の状態の検証 |
| 既存仕様書と操作手順 | 承認後に追加機能を反映 |

- 既存の JPEG コピーによるタスク間受け渡しを利用する。
- 撮影処理を `/stream` の接続状態から独立させる。
- ローカル推論ブリッジに Jev 通信を混在させない。
- JSON 検証には承認済みの `espressif/cjson` を使用する。
- 既存の依存ライブラリの版は維持する。
- 撮影サイズの変更時は共有バッファ上限 96KiB も検証する。
- Jev では顔検知専用のラベルと判定結果を区別する。

### 承認済みの境界条件

- MUST: HTTPS 通信でサーバ証明書を検証する。
- MUST: API key をログ、HTML、状態取得応答へ返さない。
- MUST: 通信処理が映像配信のフレーム待機を占有しない。
- MUST: 送信を並行実行せず、待機画像を無制限に蓄積しない。
- MUST: 未設定、通信失敗、不正応答を非うつ伏せへ置換しない。
- MUST: 受信ボディの上限、キー長、判定方式の値を検証する。
- MUST: 判定方式の切替後に旧方式の処理結果を適用しない。
- SHOULD: 既定の判定方式を既存の prone-like とする。
- SHOULD: Jev モードの失敗時は自動で既存推定へ切り替えない。
- 管理画面は現在 HTTP で提供されている。
- 管理画面の API key 入力はネットワーク上で平文になる。
- NVS 保存は保存データの暗号化を意味しない。
- 画像は外部の TypeSafe API に送信される。
