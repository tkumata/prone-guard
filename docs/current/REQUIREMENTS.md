# センサー送信・エッジ判定の要件

マイコンは観測を取得・送信し、エッジは保存と Jev による判定を担当する。
お客様だけでの接続完結とセキュリティの確保を必須要件とする。
現行の動作と運用手順は [仕様](SPECIFICATIONS.md) と [環境構築と運用](SETUP.md) に記載する。
商品向けの要件には、[接続設計](CONNECTION.md) で定める未実装の機能も含む。

## 1. 目的

- MUST: マイコンは観測の取得と送信を担当する。
- MUST: エッジ側は認証、保存、判定用データ生成を担当する。
- MUST: Jev を利用するプロダクト側が、回答検証と判定品質を担当する。

## 2. スコープ

- Freenove ESP32-S3 WROOM CAM、ESP-DL の MSR + MNP と ESPDet-Pico 416。
- Switch Science Conta VL53L5CX、8×8、1 セル 1 対象。
- ST7735 搭載の 1.8-inch、128×160px、18bit TFT。縦向きの SPI 接続とする。
- Wi-Fi STA、HTTPS、JSONL、NTP。
- Rust 1.99.1 / edition 2024、macOS 27.x、Debian 13.7。
- 同じリポジトリの `edge/` に Rust アプリを配置する。
- 医療用途認証、通知アプリ、画像送信、モデル学習は対象外。

## 3. マイコンへの要求

- MUST: VGA (640×480) で撮影し、顔矩形を元のカメラの 320×240 座標系で返す。モデルがランドマークを出力する場合は、同じ座標系で返す。
- MUST: 現在の設置方向に合わせ、推論入力を反時計回りに 90 度補正する。全画面と顔の縦横比を維持し、VGA の細部を事前の縮小で失わない。
- MUST: ブラウザ未接続でも撮影・取得・送信を継続する。
- MUST: 顔検知の成否と顔矩形の面積を取得する。
- MUST: 管理画面から顔検知モデルを MSR + MNP と ESPDet-Pico 416 の間で切り替えられる。
- MUST: 既定の顔検知モデルは MSR + MNP とする。
- MUST: 選択したモデルを不揮発メモリに保存し、起動時に使用する。
- MUST: 管理画面で設定を保存できた場合は自動で再起動する。
- MUST: 深度と target_status を各 8×8 で取得する。
- MUST: TFT に深度の 8×8 ゾーンを、1 ゾーン 16×16px、全体 128×128px で表示する。
- MUST: 0〜4000mm を近いほど明るい 64 階調へ変換し、RGB666 で表示する。
- MUST: 無効セルを黒地の赤い `×` で表示する。
- MUST: 下部 32px の 1 行目に 6×16px の文字で深度状態と顔検知結果、2 行目に 8×16px の文字で凡例を表示する。
- MUST: 顔検知時は緑の `■` と顔矩形の面積を整数の px² で表示し、未検知・カメラ未取得・取得失敗時は赤の `x` を表示する。
- MUST: 管理画面から TFT の深度マップだけを左右反転できる。
- MUST: 左右反転は既定で無効とし、設定の反映後は次回表示更新で適用する。
- MUST: 再起動後も左右反転設定を復元する。
- MUST: 旧設定を保持し、旧形式では左右反転を無効として読み込む。
- MUST: 無効セル・取得エラー・更新停止を正常な距離の濃淡と区別する。
- MUST: TFT の初期化・転送失敗を記録し、表示処理の失敗で観測の取得・送信を停止しない。
- MUST: SPI 転送成功だけでパネル接続や描画成功を確認済みにしない。
- MUST: シーケンス番号、起動 ID、ベッド ID、観測時刻を付ける。
- MUST: JSONL を 1 秒周期でエッジ側へ送信する。
- MUST: ベッド ID、URL、キーの未設定時は送信しない。
- MUST: 不正な URL、未同期の時刻を用いて送信しない。
- MUST: 取得エラーと正常な未検出を区別する。
- MUST: センサーデータを永続保存しない。
- MUST: Wi-Fi STA と再接続を維持する。
- MUST: 起動時と 24 時間ごとに NTP 同期する。
- MUST: 管理画面を HTTPS と管理者認証で保護する。
- MUST: 秘密を暗号化 NVS に保存し、取得 API やログへ返さない。
- MUST: Jev 通信と映像配信を行わない。

## 4. エッジ側への要求

- MUST: デバイスキーと許可ベッド ID を検証する。
- MUST: 入力の型、配列、値、サイズを検証する。
- MUST: 保存成功後にだけ受領成功を返す。
- MUST: 観測を SQLite に保存する。
- MUST: 保存期間の初期値を 6 時間とし、起動時に変更可能にする。
- MUST: 全ベッド合計の保存上限を 100MB にする。
- MUST: DB 本体、索引、ジャーナルを容量管理する。
- MUST: 容量不足時は古いデータから削除する。
- MUST: ベッドごとに 3 分周期で直近 3 分を判定する。
- MUST: データ不足時は理由をログに記録し、Jev 送信を停止する。
- MUST: 後続周期で品質条件を満たした場合は Jev 送信を再開する。
- MUST: Jev 認証情報を環境変数から取得する。
- MUST: Jev の障害・未設定中も観測の受付を継続する。
- MUST: 受付の稼働状態を確認する API を提供する。
- MUST: 判定不能と通信失敗を非うつ伏せへ置換しない。

## 5. お客様による接続とセキュリティ

- MUST: 配布パッケージの導入から初回接続、設定変更、機器交換、解除・復旧まで、お客様だけで完結できる。
- MUST: エッジアプリにセットアップツールを組み込み、認証、入力、設定、接続確認、再開・取消しを画面から実行できる。
- MUST: エッジのローカル設定画面で STA とベッド ID を設定できる。
- MUST: URL とキーはアプリが設定し、お客様に入力やファイル編集を要求しない。
- MUST: ツールの再実行や中断で、既存の鍵・観測・無関係な機器設定を破壊しない。
- MUST: SDK、ターミナル、eFuse 書込み、証明書生成、OS の CA 登録、固定 IP、秘密ファイル編集をお客様へ要求しない。
- MUST: 初期登録は USB、機器の物理操作、機器固有コードで認証し、Security 2 で暗号化する。
- MUST: 登録済み機器を、USB 接続だけ、LAN 探索だけ、初期登録コードだけで上書きできない。
- MUST: 通常通信は登録先の証明書・名前・期限と機器別の資格情報を検証し、不正な相手を拒否する。
- MUST: 暗号化と認証を省略する救済経路を設けない。
- MUST: 製造側で機器固有の秘密と出荷時の保護を設定・検査する。
- MUST: 鍵と証明書の生成・更新・失効をアプリが管理し、期限切れやエッジ紛失も USB 認証で復旧できる。
- MUST: 登録を世代単位で確定し、切断・電源断・保存失敗で未確定の資格情報を有効化しない。
- MUST: DHCP による IP 変更に対応し、mDNS の探索結果だけで信頼先を変更しない。
- MUST: 接続に失敗した場合は理由と再試行手順を表示し、接続成功に見せない。
- MUST: macOS と Debian の両方で、お客様の導入操作と攻撃・障害時の拒否動作を検証する。

## 6. 初期値

| 項目 | 値 |
| --- | --- |
| 顔矩形の座標系 | 320×240 |
| 顔検知 | 0 または 1 |
| 面積 | px²、小数点第 2 位まで |
| 深度 | mm、8×8、ULD の順序 |
| マイコンの全体通信期限 | 5 秒 |
| Jev の全体通信期限 | 30 秒 |
| NTP 同期間隔 | 86,400 秒 |
| 保存期間 | 21,600 秒 |
| 保存上限 | 100,000,000 bytes |
| 有効観測数 | 180 区間中 162 区間以上 |
| 連続欠測 | 5 秒以下 |
| 最新観測の経過時間 | 5 秒以下 |
| 観測の到着遅延・未来方向の時刻ずれ | 5 秒以下 |
| カメラ・深度の観測時刻差 | 1 秒以下 |
| Jev confidence | 0.9 未満は判定不能 |

上記の品質値と confidence は、エッジが使用する判定条件である。
confidence 0.9 は識別精度 90% を保証しない。

## 7. 受け入れ条件

- 正常な観測が、正しいベッドの SQLite 記録になる。
- 認証不正、許可外のベッド、不正な配列を保存しない。
- 起動 ID と番号が同じ観測を二重保存しない。
- 同じ識別子の異なる観測は競合として拒否する。
- データ不足の場合に外部 API を呼び出さない。
- 6 時間超過の観測を判定から除外し、定期削除する。
- 容量上限に達しても、古い記録を削除して最新記録を保存できる。
- 保存失敗は HTTP エラーとして返す。
- 再起動後に管理設定を復元する。
- 管理画面でどちらの顔検知モデルを保存しても自動で再起動し、選択したモデルで推論する。
- TFT に 64 ゾーンが各 16×16px で対応し、64 階調、無効セル、取得エラー、更新停止を区別できる。
- TFT の顔表示が検知時の緑の `■` と面積、未検知時の赤の `x` に切り替わり、最大面積 76800 が画面内に収まる。
- 左右反転を切り替えても、文字、上下方向、観測値と送信順序は変わらない。
- 左右反転の選択を保存でき、画面再取得と再起動後に復元できる。
- TFT と深度センサーの同時接続でも取得・送信を継続し、表示失敗を成功扱いしない。
- 実施した自動検証と未実施の実機検証を分けて記録する。
- 精度評価は実装側が担当し、未測定の値を合格扱いしない。
- [接続設計の受入条件](CONNECTION.md#7-保護する範囲と受入条件)を満たし、お客様の単独操作で接続と復旧を完了できる。
- 商品向けの接続とセキュリティは、出荷時の保護を有効にした実機でも検証する。

## 8. 制約

100MB は全ベッドの合計であり、台数別の割当ではない。
容量上限を守るため、保持期間が 6 時間より短くなる場合がある。
Jev の入力長とセンサーの識別能力は、実 API・実機で確認する。
3 分の判定周期は維持するため、連続的な即時判定ではない。
商品向け初期版の接続は、相互通信と mDNS が可能な同一 LAN を対象とする。
未対応のネットワーク条件は接続確認で案内し、セキュリティを弱めて接続しない。
